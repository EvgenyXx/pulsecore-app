# Профили Spring

Документ содержит перечень Spring Profiles, используемых в PulseCore, и описывает правила выбора конфигураций и альтернативных реализаций компонентов.

## 1. Профили окружения

| Профиль | Назначение |
|---|---|
| `local` | Локальная разработка |
| `dev` | |
| `prod` | Production-окружение |

## 2. Профили альтернативных реализаций

### 2.1. Алгоритм хеширования турниров

Компонент: `TournamentHashCalculator`.

| Профиль | Реализация | Назначение |
|---|---|---|
| `hash-legacy` | `DiscoveryHashUtil` | Предыдущий алгоритм хеширования |
| `hash-sha256` | `Sha256TournamentHashCalculator` | Алгоритм SHA-256 |

Для компонента необходимо активировать ровно один профиль.

### 2.2. Определение переноса игрока

Компонент: `TransferDetector`.

| Профиль | Реализация | Назначение |
|---|---|---|
| `transfer-standard` | `PlayerTransferDetector` | Стандартный поиск переноса игрока |
| `transfer-optimized` | `OptimizedTransferDetector` | Оптимизированный поиск переноса игрока |

Для компонента необходимо активировать ровно один профиль.

## 3. Конфигурация запуска

Профили окружения и профили альтернативных реализаций активируются совместно через `SPRING_PROFILES_ACTIVE`.

### 3.1. Локальная разработка

**SHA-256 и оптимизированный поиск переноса:**

```env
SPRING_PROFILES_ACTIVE=local,hash-sha256,transfer-optimized
```

**Предыдущий алгоритм хеширования и стандартный поиск переноса:**

```env
SPRING_PROFILES_ACTIVE=local,hash-legacy,transfer-standard
```

**SHA-256 и стандартный поиск переноса:**

```env
SPRING_PROFILES_ACTIVE=local,hash-sha256,transfer-standard
```

**Предыдущий алгоритм хеширования и оптимизированный поиск переноса:**

```env
SPRING_PROFILES_ACTIVE=local,hash-legacy,transfer-optimized
```

### 3.2. Production

Пример конфигурации:

```env
SPRING_PROFILES_ACTIVE=prod,hash-sha256,transfer-optimized
```

Выбор реализаций для production должен соответствовать проверенному поведению приложения.

## 4. Переключение реализаций

Для переключения реализации необходимо:

1. Открыть конфигурацию запуска приложения.
2. Изменить соответствующий профиль в `SPRING_PROFILES_ACTIVE`.
3. Перезапустить приложение.
4. Проверить по логам, какие реализации были зарегистрированы.
5. Убедиться в корректности обработки данных.

Пересборка приложения не требуется: выбор компонентов выполняется Spring при запуске.

## 5. Особенности переключения

### Хеширование турниров

Алгоритмы `legacy` и `SHA-256` формируют несовместимые значения хешей.

При переключении возможны несовпадения с ранее сохранёнными значениями и повторная обработка турниров.

При возврате к предыдущему алгоритму необходимо учитывать значения хешей, сохранённые после переключения.

### Определение переноса игрока

Реализации `PlayerTransferDetector` и `OptimizedTransferDetector` используют разные подходы к поиску связанных турниров.

При переключении необходимо учитывать различия в логике поиска и проверять корректность определения переноса игрока.

## 6. Актуализация документации

При добавлении, удалении или изменении профилей и альтернативных реализаций необходимо обновлять этот документ.

Перечень профилей должен соответствовать фактическим аннотациям `@Profile` и конфигурации приложения.
